## D1. 作品范围

### 推荐决定

作品固定为：

> **密码量子 Oracle 智能综合与资源评估原型**

这直接落在官方第 3 页“AI 驱动的量子编译与线路优化”和第 9–10 页“场景
锚定、严格等价、原生门适配”的交集上，同时最大限度复用现有 Boolean
Oracle 逻辑综合底座。

输入是 Boolean 函数的真值表、ANF 或内置密码坐标函数；输出是经过语义验证的
逻辑 Oracle、资源指标、原生门/映射结果、含噪执行指标及可追溯报告。

三条技术链为：

1. 等变 policy/value → Neural MCTS → 低资源逻辑 Oracle；
2. QAOA → MCTS 多样化 batch expansion；
3. 原生门/含噪评估 → 成本标定 → 重新排序或重新综合。

应用证据聚焦 AES、SM4、PRESENT、ASCON 的坐标函数，以及随机、稀疏和结构化
Boolean 函数。

### 范围控制

- 不做没有明确使用者和输入输出的大而全“量子 AI 平台”；
- GFlowNet、扩散模型、LLM Agent、QNN 和自研路由器都必须经过公平基线与
  定量退出门，不能仅凭模块名称进入竞赛主线；
- 不把旧学术论文包直接改名充当比赛作品。

### 选择后的影响

- 创新点、实验和演示围绕同一条可运行链；
- P1 研究扩展不进入 2026-09-15 最低完成门；
- 报告中的应用价值限定为“给定假设下的密码 Oracle 资源评估”。

## D2. AI 模型定位

### 推荐决定

对外统一称：

> **面向 Boolean Oracle 搜索的置换等变 policy/value 模型**

该表述能回答官方第 10 页要求的“AI 技术框架、选型依据和模型参数”，也避免
在缺少正式跨规模证据时违反“客观说明限制、避免夸大”的要求。

内部包名和 method 名可继续使用 `foundation` / `foundation_nmcts`，但当前 v3
不对外称为通用“基础模型”。

升级为“Boolean Oracle foundation model”至少需要：

- 多任务或预训练证据；
- 一个模型对多个专用模型的正式对照；
- 跨规模、跨结构、跨资源 profile 的独立测试；
- 完整训练 provenance、数据 manifest 和模型卡；
- 明确的失败域与外推边界。

### 当前证据边界

- 当前 checkpoint 只有共享主干、action head 和 value head；
- checkpoint 架构是 12 输入通道、hidden 32、2 个等变残差块、60,450 参数；
- 开发记录称训练覆盖 `n=4..10`，但训练命令、seed 和 split manifest 缺失；
- v3 只支持 `gate_mode="mct"`，且没有多资源权重训练证据。

### 选择后的影响

- “foundation”只是工程命名，不自动构成规模或通用性主张；
- 竞赛创新来自结构归纳偏置、联合 policy/value 和真实搜索贡献，而不是模型名字；
- 最终报告只有在 C0–C7 和独立测试成立后才写效果提升。

## D3. QAOA 的算法角色

### 推荐决定

QAOA 求解固定 batch 预算下的 utility-diversity 选择：

\[
\max_x
\sum_i u_i x_i
-\gamma\sum_{i<j}r_{ij}x_ix_j,
\qquad
\sum_i x_i=B_{\mathrm{eff}}.
\]

该定位把量子子程序放在一个小而明确、可由 exact 方法审计的组合优化问题上，
形成“量子计算辅助 AI 搜索”的第二方向。官方允许单向赋能或闭环，但本项目
既定目标是双向闭环；因此 QAOA 是创新增强和目标完成门，不应被包装成参赛
资格门槛或未经证实的量子加速。

实现时定义 \(K\) 为过滤和截断后冻结的候选数，
\(B_{\mathrm{eff}}=\min(B_{\mathrm{requested}},K)\)。\(K=0\) 返回空集合；
\(0<K\le B_{\mathrm{requested}}\) 直接选择全部并跳过 QAOA。

选出的每个动作各自成为独立 MCTS 子节点。QAOA 不同时施用多个
`FactorAction`，不创建 `multi_factor Plan`，也不改变现有 factor/rest
二叉递归和辅助比特成本语义。

QAOA 不是赛题参赛资格门槛。若 D3 获确认，可运行的 QAOA 调度路径属于本
项目高分目标 P0；QAOA 优于经典方法不是完成条件。在线运行时 fallback 固定
为 greedy diversity；exact diversity 仅作为小规模审计 oracle 和最优差距
基线。

必须同时实现并比较：

- random-B；
- utility top-B；
- greedy diversity；
- exact diversity；
- QAOA ideal / shot / noisy。

### 不选择旧 MWIS 的原因

- `group` 相交不是一般动作冲突关系；
- `max_factor_ancilla` 约束递归嵌套，不是同层选择数量；
- 当前候选 group-overlap 图高度稠密，旧 MWIS 容易退化为单动作；
- 现有 `Plan` 和 emitter 没有同时动作语义。

### 声明边界

- 只调用 QAOA 时称“量子子程序辅助 AI 搜索”；
- 只有带外部锁的 QAOA 最终测量 bitstring-count observation 被审计 trainer 消费、
  更新 policy/value，并在锁后未见集上通过因果消融，才称“算法级反馈闭环”；当前
  E6-v2 只有 replay 结构合同，不记录 optimizer trajectory，也尚未训练模型；
- 没有公平预算和墙钟证据时，不使用“量子加速”或“量子优势”。

## D4. 硬件证据路线

### 推荐决定

最低交付采用：

> **本地、参数可追溯的 simulator-first 硬件兼容与含噪验证**

官方要求兼容超导、离子阱、光量子等路线并提供验证数据，同时又提供真机和
仿真资源申请。simulator-first 保证截止期和复现不依赖外部排队；若平台权限
获批，再增加少量、独立标注的真机样例，不能用其替代本地可复现主证据。

至少包括：

1. 逻辑 MCT 到实际分解和目标原生门集；
2. 全连接理想 profile 与超导耦合图 profile；
3. placement、routing、SWAP 和映射后深度；
4. 独立等价性验证；
5. 含噪任务正确率或输出保真度；
6. calibration/test 隔离的成本标定与闭环前后比较。

### 真机定位

- 真机不是最低完成门；
- 平台、SDK、排队和机时可控时，只增加少量代表样例；
- 真机、仿真器和逻辑代理结果必须分栏；
- simulator 结果不能写成天衍或其他真机表现。

### 选择后的影响

- 截止期不依赖外部平台可用性；
- 所有硬件参数、软件版本、随机种子和噪声配置必须进入 manifest；
- 光量子等不适用门模型只做 capability/adapter 边界，不伪造统一门级结果。
