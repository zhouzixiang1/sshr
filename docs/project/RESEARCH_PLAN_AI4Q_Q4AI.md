## 2. 已确认冲刺方案

### 2.1 目标闭环架构（待实现并在 held-out 上验证）

```
        ┌────────────────────────────────────────────┐
        │  ① AI 赋能量子(赛题方向一.2 量子线路综合)   │
        │     等变表示 + 学习 value + MCTS            │
        │     → 低 T-count 布尔 oracle                │
        └────────────────┬───────────────────────────┘
                         ▼
        ┌────────────────────────────────────────────┐
        │  ② 硬件适配层                               │
        │     MCT → 实际分解 → 原生门集               │
        │     → 拓扑路由 → ideal/noisy simulator       │
        └────────────────┬───────────────────────────┘
                         ▼
        ┌────────────────────────────────────────────┐
        │  ③ 量子子程序辅助 AI                        │
        │     QAOA 多样化 batch 调度 MCTS 子节点       │
        │     → 已验证轨迹更新 policy/value            │
        └────────────────┬───────────────────────────┘
                         │ 含噪仿真执行指标
                         ▼
        ┌────────────────────────────────────────────┐
        │  ④ 执行反馈闭环                             │
        │     profile-specific 成本 → 改进综合策略     │
        └────────────────┬───────────────────────────┘
                         └──────► 回到 ①
```

① 是主贡献，③ 和④分别提供算法级与工程级增强。只有 replay-buffer 更新和
held-out feedback 改善完成后才称闭环；否则分别称量子辅助调度和含噪评估。

### 2.2 已确认场景锚定：密码安全

赛题要求"锚定具体的应用领域"。发榜方中电信量子集团主营量子通信/计算/测量,行业覆盖政务、应急、工业、金融。

**推荐场景：密码分析中的 Oracle 成本评估。**

理由:
1. 项目已有 AES S-box 八个**坐标函数**的完整 \(2^8\) 真值表验证，旧逻辑
   score 改善 46.36%–55.06%
2. Oracle 的 T-count、深度和辅助位是 Grover 类密码分析成本的重要组成，
   但不能单独代表完整 AES 攻击成本
3. 与发榜方业务(量子安全)高度契合
4. 可为密码资产风险分析提供“给定假设下的资源估计”，不直接给出确定迁移年限

### 2.4 各工作包要点

---

#### H1. 硬件适配层 【逻辑 QASM 已有，原生门及噪声仍为空】

**现状：** `emit_plan_to_circuit` 输出 X/CNOT/MCT 逻辑门序列；已有
OpenQASM 3 交换文件仍保留 MCT，不包含显式分解、placement、routing 或噪声。

**要做：**

1. Plan → 逻辑 X/CNOT/MCT → 逻辑 OpenQASM 交换文件；
2. 按目标 profile 做显式 MCT 分解、原生门转换、映射与必要路由；
3. 超导路线完成局部耦合图、CX/ECR 类门、SWAP、理想/含噪仿真和反馈标定；
4. 离子阱路线完成全连接 profile、RXX/MS 类相互作用、资源映射和理想等价；
5. 光量子路线只提交 capability/adapter/unsupported-boundary 表，不伪造统一
   门级兼容；
6. 分别完成逻辑 QASM 交换保真和映射后原生线路的独立理想等价验证。

**实现路径：** Qiskit transpile/Aer 提供强基线；另实现严格限域的
Oracle-aware noise-weighted window router，只负责已分解 1/2-qubit 静态
Oracle 的 SWAP 插入和 layout 更新，不声称通用路由器。最终选型须通过许可证、
环境锁定和干净安装验证。

**风险：** 天衍 SDK/机时不可控，因此不得把真机列为关键路径。若申请成功，
只增加少量代表样例；本地 simulator 结果与真机结果必须分开表述。

#### A1. 学习 value network + expert iteration

沿用 v2 方案(见第 5 节)。竞赛语境下的额外价值:赛题要求"**成本降低比例**"这类实测数字,A1 若能把运行时从 +91% 转负,就是一个干净的"计算成本降低 X%"指标。

**成功判据:** score 不劣 + 运行时下降 + 消融显示 AI 不可删。

---

#### Q2. 布尔结构–量子资源图谱（P1 探索）

它是论文扩展，不是竞赛双向链的必要支点。竞赛的量子→AI 链由 QAOA
多样化调度承担。

**关键:** Stab-QRAM(arXiv 2509.26494)证明仿射布尔函数零 T-count 并**明确把非仿射留作开放问题**;本引擎处理任意非仿射函数。AES S-box(按高非线性度设计)是谱线高端锚点,现有 affine 消融是低端。

---

#### V1. 含噪仿真 + 资源模型标定

**核心思路:把项目最大的局限变成一个实验。**

项目的逻辑 depth 和 T-depth 都是代理，尚未在原生门执行层得到验证。

**做法：** 取小规模 Oracle，在冻结硬件 profile 和噪声模型下完成原生门映射，
测量任务级成功率，回归分析逻辑资源、原生门资源与模拟成功率的关系。

**产出：** “在给定 simulator profile 下，逻辑/原生资源与含噪成功率的相关性
及其置信区间”。不能写成真机实测相关性。

**同时满足赛题"避免夸大"要求:** 明确报告代理失效的区间。

---

#### C1. 闭环 —— simulator feedback 重标定

**这是把"双向"做成"闭环"的关键一步,且技术上很干净:**

1. 项目的历史加权目标是
   `score = 1.0·T + 0.04·CNOT + 0.015·depth + 0.01·gates + 2.0·ancilla`；
   它是逻辑层经验 profile，尚未由执行层数据标定
2. 用 V1 的含噪仿真数据拟合受约束的执行成本代理
3. 用重标定后的权重重跑综合,量化改进

**逻辑链路：** AI 综合线路 → 原生门/含噪仿真 → profile-specific 反馈 →
重标定目标 → AI 重新综合。它是 simulator-calibrated 工程闭环，不代表真机反馈。

这比 v2 方案里"用引擎综合神经网络自身的 oracle"那个示意性演示要**扎实得多**,建议替换。

---

#### S1. 密码安全场景包 【落地与价值】

- 扩展 AES S-box 到更多密码原语的 oracle 成本表
- Grover 类密码分析的分层资源估计：分别报告 Oracle 逻辑资源、超导 profile
  映射资源及明确假设下的算法级外推，不称完整攻击端到端实测
- 给定攻击模型和硬件假设下的密码资产资源风险讨论
- **应用价值：** 为运营商/政企客户提供可审计的 Oracle 成本，而不是直接
  预测“现有密码资产还安全多久”

## 4. 风险与边界

### 4.1 禁区(即使赛题提到也不要碰)

赛题方向(二)2 列出了量子神经网络、贫瘠高原等题目。**不建议本项目切入**:

| 方向 | 不碰的理由 |
|---|---|
| 变分 QML / VQC / QNN | 无 barren plateau ⟹ 可经典模拟(*Nature Communications* 2025)。规避 BP 的策略同时杀死量子优势。且与本引擎零关联,等于从头开始 |
| Grover 式 ML 加速 | 二次加速,纠错后退化为四次方;数据加载主导运行时 |
| 声称"量子 AI 有优势" | 赛题明文要求"避免夸大量子 AI 的实际效能" |

**本项目的 Q4AI 落点是 oracle 成本,不是 QNN。** 文献已确认"oracle 构造的 T-count 已成为 data-dependent 量子算法的实际瓶颈",这是有据可依的切入点。
